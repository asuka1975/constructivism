# 日本語文書の構成選択

## 目的
与えられた目的・読者・メッセージ・内容から文書構成を1つ選び、本文執筆の前に使う「骨子」を出力する。事実は整理済み、論理は検証済みとして扱い、内容の追加や論証の修正はしない。

## 1. 入力の受け取り方
ハーネスから次の項目を受け取る。欠けている項目は（ ）内の既定値で補い、出力の「仮定」欄に明記する。
- 目的：読者が読後に何をするか（決める／報告を受ける／作業する／学ぶ／調べる／理解する／動かされる／検証する）
- 読者：役割、専門性（初学者／中級／専門家。既定は中級）、読む姿勢（通読／拾い読み／冒頭だけ。役職者は冒頭だけ）
- メッセージ：中心となる主張・結論（1〜2文）と種別（提言／決定の記録／事実報告／手順指示／概念説明／比較評価／教育）
- 内容：手順的／概念的／参照的／時系列／データ中心、および主要な要素の一覧
- 制約：指定書式、媒体（メール／Wiki／Web／PDF）、分量上限、社内か社外か（既定は社内・Web）

## 2. 判断手順
1. **定型の確認**：組織の様式・投稿規定・法令書式が指定されていればそれを骨格とし、手順4以降で中身を調整する。
2. **系統の決定**：目的からジャンルの候補を2つ選ぶ。LOAD references/decision-rules.md（決定木と選択マトリクス）
3. **型の決定**：メッセージ種別で型を確定する（判断を求めるなら PREP か SCQA、報告なら SDS、決定の記録なら ADR、学術なら IMRaD）。
4. **結論の位置**：既定は冒頭（結論ファースト）。次の場合だけ変える。
   - 学習順序に意味がある → 冒頭に完成像と学習目標、本論は積み上げ
   - 状況が共有されていない、または反対が予想される → SCQA で状況と複雑化を短く述べ、答えは第1段落内に置く
   - 論文 → 要旨に結論、本文は IMRaD の順
   - 起承転結（「転」で話題を転じる構成）は使わない
5. **深さの調整**：初学者向けなら前提条件・用語定義・例を独立したセクションにする。専門家向けなら背景を1段落か付録にまとめる。
6. **媒体と分量への適合**：メールなら件名で要件、冒頭で結論と依頼を示す。Web なら H2 を目次として機能させる。分量の上限があれば第2階層を統合し、第1階層の順序は保つ。
7. **骨子の作成**：該当するカタログを読み込み、定番骨子を入力内容に合わせて具体化する。
   - 技術系：LOAD references/catalog-technical.md
   - 論文・教材：LOAD references/catalog-academic-edu.md
   - ビジネス系：LOAD references/catalog-business.md
   - 文体・標題・見出しの規則：LOAD references/japanese-conventions.md
   - 目的が複数、または定番から外れる場合：LOAD references/hybrid-and-checklist.md

## 3. 出力形式
次の Markdown で出力する。見出しは内容を表す具体的な名詞句か文にし、「その他」「概要2」のような見出しは使わない。形式に迷ったら入力→出力の例を参照する：LOAD examples/sample-outputs.md

    ## 構成選択結果
    - 採用構成：<ジャンル名>（型：<PREP/SDS/SCQA/IMRaD/Diátaxis種別 等>）
    - 第2候補：<ジャンル名> — 採用しなかった理由：<1文>
    - 選択理由：<読者の目的・読む姿勢・メッセージ種別にどう対応するか 2〜3文>
    - 核メッセージの位置：<冒頭/末尾/両方> — <どのセクションの何文目か>
    - 文体：<敬体/常体> 標題案：<主題＋文書の性格>
    - 仮定・逸脱：<補った入力、定番からの逸脱とその理由>

    ## 骨子
    1. <見出し>（役割：<1文>／目安：<字数または割合>）
       - 入れる要素：<入力内容のどれを置くか>
    2. ...

    ## 構成チェック
    - [x]/[ ] 各項目（下記5.の結果）

## 4. 原則
- 1文書1主目的。目的が2つあるときは区画に分けるか、文書の分割を提案する。
- 1セクション1目的。手順と概念、事実と意見を同じセクションに混ぜない。
- 標題で主題と文書の性格（報告・提案・依頼・お知らせなど）を示す。
- 見出しだけで筋が通るようにする。同じ階層の見出しは MECE で、粒度をそろえる。
- 定型ジャンルでは必須セクションを削らない（該当しない場合は「該当なし」と書く）。

## 5. 最終チェック
出力前に確認し、結果を「構成チェック」に記す。
- 主要メッセージが冒頭3文以内にあるか（積み上げ型なら、完成像か目標が冒頭にあるか）
- 見出しだけで筋が通るか。標題と見出しが呼応しているか
- 各セクションの目的が1つか。同じ階層の見出しが MECE か
- 読者の目的に不要な章がないか。範囲・前提・扱わないことを宣言しているか（長文の場合）
- 意思決定文書に代替案・リスク・判断事項があるか。定型の必須セクションがそろっているか
- 文体がジャンルの既定に合い、統一されているか
