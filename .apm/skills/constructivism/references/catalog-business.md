# 構成カタログ：ビジネス文書系

出典：調査レポート 3.3「ビジネス文書系」。各ジャンルを「適用条件／骨子／メッセージの位置／目安分量／アンチパターン／日本語の慣習」の6項目に統一して転記した。レポートに記載のない項目は「レポートに記載なし」と明記し、レポートの他章（第2章の決定木・選択マトリクス、第4章の文体の既定、5.1 のハイブリッド指針）から補える場合のみその旨を付して補った。レポートの根拠・備考は「適用条件」の補足として残した。

分量の目安はレポートの経験則で、一次情報で規定されている数値はその旨を明記している。文体の既定（第4章）：論文・リファレンス・仕様書・ADR は常体、それ以外は敬体。

## 似たジャンルの判別表

レポート自身が区別の基準を書いている組み合わせだけを載せる。

| 迷う組み合わせ | 前者を選ぶ条件 | 後者を選ぶ条件 | 出典 |
|---|---|---|---|
| 報告書 vs 企画書 | 事実を渡して理解させる（SDS） | 判断と行動を求める（PREP・SCQA） | 3.3 |
| 稟議書 vs 企画書・提案書 | 金額・権限の決裁を求める | 新規施策の採否を求める（長文なら Amazon 型ナラティブ／PR/FAQ） | 2.2 決定木 |
| エグゼクティブサマリー vs 報告書 | 要点だけ知りたい読者に A4 1枚で結論・根拠・判断を渡す | 要点→詳細→要点で全体像を渡す。長い報告書は「エグゼクティブサマリー＋本体」の二層構成 | 2.2、2.3、5.1 |
| 社内通知 vs 依頼・説得メール | 周知する（行動と期限を最初に示す） | 特定の相手に依頼・説得する（PREP、訴求文は AIDA） | 2.2、2.3 |
| ポストモーテム vs 障害報告書（社外向け） | 関係者が通読し、影響・原因・対策を定位置に置く | 社外向け。冒頭にお詫びと影響範囲を置き、技術的詳細は後段に回す | 2.3、3.3 |
| PREP vs SDS（型の選択） | 判断や行動を求める | 理解と情報共有 | 第4章 |
| チュートリアル vs ハウツー | 初学者が手を動かして初めて成功する。読者はまだ「何がわからないかもわからない」 | 目標を持つ実務者が特定の課題を解く | 3.1 |
| リファレンス vs ハウツー／解説 | 検索して事実を確かめる。製品の構造に従って組み立て、使い方の物語を混ぜない | 概念の説明は解説へ、網羅的なオプション一覧はリファレンスへ回し、ハウツーは目標達成への最短経路に絞る | 3.1 |
| 解説記事 vs 技術記事 | 「なぜそうなっているか」に答える（概念の説明、中級者・通読） | 経験や知見を共有する（主張と経験、開発者・拾い読み） | 2.3、3.1 |
| デザインドキュメント vs ADR | 解決策があいまいで、技術方式の合意が必要 | 決定済み事項を1決定1記録で残し、時点の文脈を保存する | 2.2、2.3、3.1 |

## 報告書（SDS 型）

- **適用条件**：事実を渡して理解させる文書（SDS）。第2章の決定木では「報告を受ける」のうち「進捗・調査結果」。
  - 備考：報告書と企画書の違いは、報告書は事実を渡して理解させる（SDS）、企画書は判断と行動を求める（PREP・SCQA）。
- **骨子**：標題（「〜に関する報告」と文書の性格を明示）→ 要旨（結論・要点を3行程度）→ 背景・目的 → 経過・実施内容 → 結果 → 考察・課題 → 今後の対応 → 添付資料
- **メッセージの位置**：冒頭と末尾の両方。
- **目安分量**：要旨は3行程度。それ以外はレポートに記載なし。
- **アンチパターン**：時系列の日誌になり、結論が最後まで出ない。
- **日本語の慣習**：標題で「〜に関する報告」と文書の性格を明示する（骨子の記述から）。文体の既定は敬体（第4章）。

## 企画書・提案書

- **適用条件**：判断と行動を求める文書（PREP・SCQA）。第2章の決定木では「承認・決定する」のうち「新規施策の採否」。長文なら Amazon 型ナラティブ／PR/FAQ。
- **骨子**：提案の要旨（何を・いくらで・何が得られるか）→ 現状と課題（SCQA の S と C）→ 提案内容 → 期待効果（定量）→ 実施計画・体制 → 費用 → リスクと対策 → 代替案との比較 → お願いしたい判断
- **メッセージの位置**：冒頭。
- **目安分量**：レポートに記載なし。
- **アンチパターン**：課題の説明に紙幅を使い切り、判断してほしい事項がない。
- **日本語の慣習**：レポートに記載なし。文体の既定は敬体（第4章）。

## エグゼクティブサマリー／1枚もの

- **適用条件**：レポート 3.3 に記載なし。第2章の決定木では「要点だけ知る」→ エグゼクティブサマリー／1枚もの（BLUF）。5.1 では、長い企画書・デザインドキュメント・報告書は「エグゼクティブサマリー＋本体」の二層構成を既定とする。
- **骨子**：結論・提言（1〜2文、BLUF）→ 根拠3点（ピラミッドの第2階層、MECE）→ 必要な判断・期限 → 主要数値 → 詳細資料への参照
- **メッセージの位置**：冒頭の「結論・提言」（骨子の記述から）。
- **目安分量**：A4で1枚。結論・提言は1〜2文。
- **アンチパターン**：本文を縮めただけの要約（結論がない）。
- **日本語の慣習**：レポートに記載なし。文体の既定は敬体（第4章）。

## Amazon 型ナラティブ（6ページャー）・PR/FAQ

- **適用条件**：重要な意思決定を文章による深い検討で行うとき。会議の冒頭で黙読される前提で書く。
- **骨子**：
  - PR/FAQ：将来の発表日付のプレスリリース（1ページ未満）と FAQ（5ページ以内）。
  - 汎用ナラティブ：目的（何を議論し決めたいか）を先頭に置き、その後は目的に合わせて組み立てる。四半期レビューの例は「導入／原則／成果／未達／次期の提案／人員／損益／FAQ」。
- **メッセージの位置**：汎用ナラティブでは先頭の「目的」（骨子の記述から）。PR/FAQ についてはレポートに記載なし。
- **目安分量**：PR は1ページ未満、FAQ は5ページ以内。この分量の上限は、『Working Backwards』の著者で元 Amazon 社員の Colin Bryar と Bill Carr による規定（About Amazon 掲載の書籍抜粋：PR は "always less than one page"、FAQ は "five pages or less"）。
- **アンチパターン**：レポートに記載なし。
- **日本語の慣習**：レポートに記載なし。文体の既定は敬体（第4章）。

## 議事録

- **適用条件**：レポート 3.3 に記載なし。第2章の決定木では「報告を受ける」のうち「会議」→ 議事録（決定事項先頭）。
- **骨子**：会議名・日時・場所・出席者 → 決定事項 → 宿題事項（担当・期限）→ 議題ごとの討議要旨 → 次回予定
- **メッセージの位置**：決定事項と宿題を冒頭に。
- **目安分量**：レポートに記載なし。
- **アンチパターン**：発言の逐語的な羅列、決定と意見の区別がない。
- **日本語の慣習**：公用文の考え方は議事録を「記録・公開資料等」に分類し、公用文表記を基本としつつ読み手に合わせた工夫を認めている。

## 稟議書・決裁文書

- **適用条件**：レポート 3.3 に記載なし。第2章の決定木では「承認・決定する」のうち「金額・権限の決裁」。
  - 根拠：単一の公的標準はなく、社内様式が最優先（Q0）。下の項目は複数の実務解説で共通しているもの。
- **骨子**：件名（対象＋行為＋目的。「〜について」で終わらせない）→ 起案者・起案日 → 決裁を求める事項（結論）→ 目的 → 理由・背景 → 実施内容 → 金額と内訳 → 期待効果 → リスクと対策 → スケジュール → 添付資料（見積・比較表）
- **メッセージの位置**：件名と「決裁を求める事項」。
- **目安分量**：レポートに記載なし。
- **アンチパターン**：目的が部署の都合になっている、代替案や比較がない。
- **日本語の慣習**：件名は対象＋行為＋目的で書き、「〜について」で終わらせない（骨子の記述から）。文体の既定は敬体（第4章）。

## プロジェクト計画書（一次情報未確認・一般的な実務慣行）

- **適用条件**：レポートに記載なし。
- **骨子**：目的と成功基準 → スコープ（含む・含まない）→ 成果物 → スケジュールとマイルストーン → 体制と役割 → 予算 → リスク管理 → コミュニケーション計画 → 変更管理
- **メッセージの位置**：レポートに記載なし。
- **目安分量**：レポートに記載なし。
- **アンチパターン**：レポートに記載なし。
- **日本語の慣習**：レポートに記載なし。文体の既定は敬体（第4章）。

## 障害報告書・ポストモーテム

- **適用条件**：レポート 3.3 に記載なし。第2章の決定木では「報告を受ける」のうち「障害」→ ポストモーテム。選択マトリクスでは読者「関係者・通読」、メッセージ種別「事実と再発防止」に対応し、第2候補は障害報告書（社外向け）。
- **骨子**（Google SRE 本のテンプレートに準拠）：表題（インシデント番号）→ 日付・作成者・ステータス → 要約 → 影響 → 根本原因 → トリガー → 解決 → 検知 → アクションアイテム（担当・期限）→ 教訓（うまくいったこと・うまくいかなかったこと・運が良かったこと）→ タイムライン
  - アクションアイテムは「調査・緩和・修復・検知・予防」に分類し、少なくとも緩和と予防を含める（Google SRE の Lunney ほか、USENIX ;login: 2017年春号）。
- **メッセージの位置**：レポート 3.3 に記載なし。選択マトリクスの選択理由は「影響・原因・対策を定位置に置く」。
- **目安分量**：レポートに記載なし。
- **アンチパターン**：非難の物語になる、オーナーのいない対策。
- **日本語の慣習**：社外向けの障害報告では、冒頭にお詫びと影響範囲を置き、技術的詳細は後段に回す。文体の既定は敬体（第4章）。

## 社内通知・案内

- **適用条件**：レポート 3.3 に記載なし。第2章の決定木では「動かされる」のうち「周知」→ 社内通知。選択マトリクスでは読者「社員全体・冒頭だけ」、メッセージ種別「周知」に対応する。
- **骨子**：標題（「〜の変更について（お知らせ）」のように性格を明示）→ 要点（誰が・何を・いつまでに）→ 詳細（「記」以下に箇条書き）→ 問い合わせ先
- **メッセージの位置**：レポート 3.3 に記載なし。選択マトリクスの選択理由は「行動と期限を最初に示す」。
- **目安分量**：レポートに記載なし。
- **アンチパターン**：レポートに記載なし。
- **日本語の慣習**：公用文の考え方の「標題で主題と文書の性格を示す」「三つ以上の情報は箇条書」「『下記』『別記』を適切に活用」がそのまま使える。文体の既定は敬体（第4章）。

## 依頼・説得メール

- **適用条件**：レポート 3.3 に記載なし。第2章の決定木では「動かされる」のうち「依頼・説得」→ 依頼メール（PREP）・訴求文（AIDA）。選択マトリクスでは読者「社外・通読」、メッセージ種別「依頼」に対応する。
  - 型：判断や行動を求めるなら PREP、情報共有なら SDS（日本の実務解説で共通する使い分け）。訴求文には AIDA（注意→関心→欲求→行動）。
- **骨子**：件名（要件と期限）→ 宛名・挨拶（1行）→ 結論：依頼事項 → 理由・背景 → 具体的にお願いしたいこと（箇条書き・期限）→ 結び
- **メッセージの位置**：レポート 3.3 に記載なし。選択マトリクスの選択理由は「依頼事項と期限を冒頭に」。
- **目安分量**：宛名・挨拶は1行。それ以外はレポートに記載なし。
- **アンチパターン**：前置きの挨拶が長く、依頼が3段落目に出てくる。
- **日本語の慣習**：レポートに記載なし。文体の既定は敬体（通知・依頼など特定の相手に向けた文書は敬体、第4章）。
